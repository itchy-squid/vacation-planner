Stays, daily prices and idea types

Three related asks for the Yucatán-style trip flow: ideas that are somewhere you sleep or set off from rather than something you do, prices that repeat each night or day, and a way to sort ideas by type so the board and map can filter on it. Screens use the app's own tokens and components. Tap the controls on the cost and board screens; they work.

Feature 1

Mark an idea as a stay or a starting point

A stay or a starting point is still an idea. You can search for it, heart it, put it on the map, and compare it against another hotel. What changes is how it's used. It never takes up time on the Plan tab, and its cost is counted per night instead of once.

Today: a day's Staying at (Where we'll be) can point at any idea that's on the map, so the hotel is mixed in with the cenotes. The only way to count a hotel's cost is to place it (or a "Lodging" custom item) in a block on the timeline, and that block takes up activity hours. There's no way to say where day 1 starts if you aren't at the hotel yet, like landing at the airport.

1a · Edit idea: what is this?

A type picker at the top of Edit Visit. Picking Stay swaps How long for check-in and check-out times and sets the price to per night. The full type list is in feature 3.

How to mark it

  1. A type on the idea, with Stay and Start point as two of the types. Recommend One field. It doubles as the filter in feature 3, and hotels can still be hearted and compared like any other idea.
  2. A "This is lodging" switch on the idea, separate from tags. Smaller, but then types (feature 3) are a second, overlapping field.
  3. A separate Stays list, not ideas at all. Cleanest data, but you lose search, hearts and the map, and comparing two hotels needs its own screen.

Open questions for you

  • Should the "Lodging" custom item in Plan's + Add go away and become "add a stay idea"? Leaving both is confusing.
  • Should check-in show as a short block (1c shows it that way) or only as a time on the band?
  • Start point: is a trip-wide setting (1d) plus a per-day override enough, or do you also want a start point for a single plan or route?
  • On a split day (two groups), can each group sleep somewhere different?
Feature 2

Prices per night or per day

The cost field gets a second choice next to Per person / For the group: how often you pay it. The count comes from the trip itself. Nights come from the stay's booked nights, and days come from the days you pick, so the total updates when the plan changes.

Today: every idea and custom item has one price, either per_head or group, counted once each time it's placed in a plan. A $65/day rental car for 3 days has to be typed in as $195, and it's wrong if the plan changes.

Where the count of nights or days comes from

  1. From the trip: nights from the stay's booked nights (1b), days from a day picker that starts with the days it's on the plan. Recommend The total follows the plan and nobody types a number twice.
  2. A typed count ("for 3 days"). Simplest, but it drifts out of date when the plan moves.
  3. Only from the plan: count the days it's placed on the timeline. Doesn't work for a stay, which never goes on the timeline (feature 1), or a car you have all day.

Open questions for you

  • Per night is really a per-day price with a different count (nights = days − 1). Is it worth two buttons, or should Stay always mean per night and everything else offer only Once / Per day?
  • Taxes and one-off fees on a stay (a $90 cleaning fee): a second "plus once" amount, or a separate idea?
  • If a per-day item is on a split day, does only that group pay for that day?
Feature 3

Types and tags you can filter by

Each idea gets exactly one type, which has an icon and drives the map marker, and any number of tags for everything else. The board and the map filter on both. Tags stop being a fixed list, so anyone planning can add one for the trip.

Today: ideas have tags from a fixed list of seven (outdoors, food, swim, hike, sunset, rainy-day, kid-ok), but nothing filters by them. The board only filters by region, and the map shows every idea the same way.

Types, tags, or both

  1. One type plus free tags. Recommend Types are few and fixed, so they can have icons and drive the map and the Stay/Start behaviour. Tags stay flexible.
  2. Tags only, with special tags like lodging. Fewer fields, but an idea can be both "lodging" and "food", and the map can't pick one icon.
  3. Types you can edit per trip. Most flexible, but Stay and Start point have to stay built in because the app behaves differently for them.

Open questions for you

  • Is the 8-type list above right? Beach vs. Outdoors and Shopping are the usual arguments.
  • Should existing ideas get a type guessed from their tags and Google place category, or start as "Other" until someone picks?
  • Should the board's filter be remembered per device (like Expenses' scope) or reset each visit?
  • Should Plan's + Add picker get the same type filter?

What it would change underneath

A sketch only, to show the size of the work. Nothing here is decided.

Ideas (pins)

  • type: one of the eight types, default other. Stay and Start point skip duration_minutes.
  • cost_per: once / night / day, next to the existing cost_basis. Old ideas are once, so no total moves.
  • check_in / check_out times for stays. cost_days (dates) for per-day items.

Trip and days

  • trip_day_places.lodging_pin_id already exists. Booking nights (1b) just sets it on several days at once.
  • New trip-level start and end point plus time (1d), and an optional per-day start override.
  • A per-trip tag list, so + New tag is shared and tags can be renamed or merged.

Money

  • derive.py item_money multiplies by nights or days before dividing by who's going. The per-head-is-a-division rule stays.
  • Expenses reads stays from Where we'll be, not from plans, since a stay is never placed in a block.
