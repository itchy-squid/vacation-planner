Route proposals from the calendar

Every proposal is now built in the map planner, including the calendar's + Add, reopened drafts, adding a set to a vote and editing a set. The old Propose a block screens (pick hours, fill them, review) go away. Each proposal has a Starts time you set directly. Custom events can be stops even when they have no place on the map. Frames marked live respond to taps.

What changes

  • Entry points. AddSheet, the draft tray on DaySchedule and the Add a set / Edit buttons on CompareSets all go to /map/trip. They pass day, and a draft, a vote to join, or a set to edit. Back and Cancel return to where you came from.
  • ProposeBlock retires. Its work moves into PlanTrip: loading a draft or set, the discard prompts, save-in-place, withdraw, and cleaning up custom events on abandon.
  • Starts. Replaces the − / + leave-time row with a field next to the day, shown from the first stop. DEFAULT_LEAVE_MIN becomes a fallback for when no open slot fits.
  • Stops without a location. buildTrip needs to accept a stop with no coordinates. It borrows the location of the stop before it, so no ride is added.

Rules for a vote's fixed hours

  • A set joins a vote only if its hours match exactly. So in frames 9 and 10 the block is the vote's hours, and the route sits inside them with spare time at either end.
  • If the route runs past the vote's hours, the button is disabled with a note saying how far over it is. Removing a stop or shortening one fixes it.
  • Start and end lodging stay outside the block, as in the current review.

Still open

  • Splits. ProposeBlock lets you pick which group a block is for when the day is split. Where does that go in the planner: a chip row under the day, or taken from the day view you came from?
  • Costs. ProposeBlock shows a budget strip and per-stop costs. The trip review shows fares only. Should stop costs carry over?
